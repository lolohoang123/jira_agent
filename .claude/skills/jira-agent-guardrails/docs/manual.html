jira-agent-guardrails

jira_agent リポジトリを CLAUDE.md の「絶対ルール」に照らして機械的に検査するスキルです。

Skill kiểm tra tự động repo jira_agent theo các "quy tắc bắt buộc" trong CLAUDE.md.

1. 使い方 / Cách sử dụng

Claude Code で次のように依頼します。スクリプトが先に実行され、違反があれば file:line と修正案が返ります。

Yêu cầu Claude Code như dưới đây. Script chạy trước; nếu có vi phạm, Claude trả về file:line và cách sửa.

/jira-agent-guardrails
「approval/ を変更したのでガードレールを確認して」
"Kiểm tra guardrails trước khi commit giúp tôi"

手動実行（CI でも同じコマンド）：

Chạy thủ công (CI dùng cùng lệnh):

python .claude/skills/jira-agent-guardrails/scripts/check_guardrails.py .
# exit 0 = OK, exit 1 = ERROR あり / có lỗi ERROR

3. なぜこの設計か / Vì sao thiết kế như vậy

  • 判定はスクリプト（ast 解析）で行い、AI の読み取りに頼らない：毎回同じ結果になり、トークンも節約でき、CI でも Claude なしで動く。 Phán định bằng script (phân tích ast), không dựa vào AI đọc code: kết quả luôn giống nhau, tiết kiệm token, chạy được trong CI mà không cần Claude.
  • コードを import・実行しない：環境変数や AWS 認証情報がなくても安全に検査できる。 Không import hay chạy code: kiểm tra an toàn kể cả khi thiếu biến môi trường hoặc thông tin AWS.
  • 各ルールは CLAUDE.md の規則か、実際に起きた不具合に対応する。根拠のないルールは誤検知を増やすだけ。 Mỗi quy tắc tương ứng một quy định trong CLAUDE.md hoặc một lỗi đã xảy ra thật. Quy tắc không có căn cứ chỉ làm tăng báo động giả.
  • 300 秒は数値で厳密に照合する（"> 3000" を見逃さないため）。 Số 300 được so khớp chính xác (để không bỏ sót "> 3000").
  • テスト（tests/test_guardrails_skill.py）は実コードをコピーして違反を 1 つずつ注入し、各ルールが検出することと誤検知がないことを保証する。 Test (tests/test_guardrails_skill.py) sao chép code thật, chèn từng vi phạm một, bảo đảm mỗi quy tắc đều phát hiện được và không có báo động giả.

4. 防いでいる失敗 / Những lỗi được ngăn chặn

Rule実例 / Ví dụ thực tế
G1承認を経ずに Jira に書き込む run_create_worklog_task.py が残っていた（このスキルが初回実行で検出）。Còn sót run_create_worklog_task.py ghi Jira mà không qua duyệt (skill phát hiện ngay lần chạy đầu).
G3llm_client.py の print() がモデル出力（作業内容を含む）を CloudWatch に出していた。print() trong llm_client.py ghi output của model (kèm mô tả worklog) ra CloudWatch.
G6TransactWriteItems が本番で "operand type: M" で失敗。モックのテストでは検出できなかった。TransactWriteItems lỗi trên production với "operand type: M"; test dùng mock không phát hiện được.
G4リプレイ窓を広げる・秘密鍵の比較を == にする、といった「小さな変更」で認証が弱まる。Những "thay đổi nhỏ" như nới cửa sổ replay hay so sánh secret bằng == làm yếu xác thực.

限界：静的解析なので、変数名に機密を示す語がない値のログは検出できません。振る舞いは単体テストで保証します。

Giới hạn: đây là phân tích tĩnh, nên không phát hiện được log giá trị nhạy cảm nếu tên biến không gợi ý điều đó. Hành vi được bảo đảm bằng unit test.

5. ルールを変えるとき / Khi muốn đổi quy tắc

チェックを通すためにルールを弱めてはいけません。変更する場合はユーザーの明示的な承認を得て、CLAUDE.md・guardrail-rules.md・テストを同時に更新します。

Không được nới quy tắc chỉ để vượt qua bước kiểm tra. Nếu cần đổi, phải có đồng ý rõ ràng của người dùng và cập nhật đồng thời CLAUDE.md, guardrail-rules.md và test.
